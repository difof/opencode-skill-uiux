- Use this guide for React or Next.js component implementation, data fetching, bundle costs, hydration, or measured rendering problems; keep existing framework, state, routing, and dependency conventions.
- This index covers all 70 rules in the pinned Vercel snapshot; each linked rule preserves its explanation, incorrect and correct examples, qualifications, and support links; open the relevant rules on demand and use the [complete guide](../upstream/vercel/react-best-practices/complete-guide.md) only for a comprehensive audit.
- Start with request waterfalls and bundles, then server and client data work, then rerenders and rendering, then JavaScript hot paths and advanced patterns; use the individual rule's impact and measured user cost rather than treating a category label as proof.
- Confirm installed React, Next.js, runtime, browser, and React Compiler support before using an API; `Activity`, `useEffectEvent`, async transitions, React DOM resource hints, `after()`, and framework import optimizers are version-dependent; a source example does not authorize dependency installation or framework migration.
- Treat source timing and speedup numbers as example measurements; preserve behavior, accessibility, authorization, privacy, error handling, and data freshness while profiling the actual project.
- The snapshot has source inconsistencies: [Effect Events](https://react.dev/reference/react/useEffectEvent) are excluded from effect dependencies and must be called from Effects or other Effect Events, not used as general stable callbacks; [transitions](https://react.dev/reference/react/useTransition) do not cancel network requests or guarantee response ordering; [Activity](https://react.dev/reference/react/Activity) preserves state and DOM while cleaning up hidden effects and can still rerender hidden children at lower priority.
- [async-cheap-condition-before-await](../upstream/vercel/react-best-practices/rules/async-cheap-condition-before-await.md): evaluate cheap synchronous guards before remote flags when they can rule out the branch; preserve ordering when the guard depends on the flag, costs more, or side effects require it.
- [async-defer-await](../upstream/vercel/react-best-practices/rules/async-defer-await.md): move an await into the branch that consumes its result and return early on skipped or missing resources; preserve required permission checks before protected operations.
- [async-parallel](../upstream/vercel/react-best-practices/rules/async-parallel.md): start independent operations concurrently with `Promise.all()`; keep actual data dependencies and intentional sequencing explicit.
- [async-dependencies](../upstream/vercel/react-best-practices/rules/async-dependencies.md): start each dependent task as soon as its own prerequisites complete; the full rule includes both `better-all` and a native promise alternative, so reuse existing tools instead of adding a dependency by default.
- [async-api-routes](../upstream/vercel/react-best-practices/rules/async-api-routes.md): start independent work early and await it late in API routes and Server Actions; avoid auth, configuration, and data waterfalls without starting protected side effects before authorization.
- [async-suspense-boundaries](../upstream/vercel/react-best-practices/rules/async-suspense-boundaries.md): stream slow regions inside deliberate Suspense boundaries while the surrounding layout renders; share a promise across consumers where appropriate, reserve fallback space, and assess layout-critical data, SEO, short queries, and layout-shift tradeoffs.
- [bundle-barrel-imports](../upstream/vercel/react-best-practices/rules/bundle-barrel-imports.md): reduce costly barrel imports with supported package subpaths or the installed framework's package import optimization; retain TypeScript declarations and editor support, and do not assume every deep path is exported or typed.
- [bundle-analyzable-paths](../upstream/vercel/react-best-practices/rules/bundle-analyzable-paths.md): use literal paths or explicit module maps for dynamic imports and server file reads so bundlers and file tracing include a narrow, predictable set of files.
- [bundle-dynamic-imports](../upstream/vercel/react-best-practices/rules/bundle-dynamic-imports.md): split heavy components that initial rendering does not need, using the existing framework's dynamic-loading mechanism; choose SSR behavior deliberately.
- [bundle-defer-third-party](../upstream/vercel/react-best-practices/rules/bundle-defer-third-party.md): defer noncritical analytics, logging, and similar third-party code until after hydration without losing required observability or consent behavior.
- [bundle-conditional](../upstream/vercel/react-best-practices/rules/bundle-conditional.md): load large modules or datasets when their feature becomes active; provide loading and failure behavior and verify the actual server/client bundle boundary.
- [bundle-preload](../upstream/vercel/react-best-practices/rules/bundle-preload.md): preload likely heavy interactions on hover, focus, or an existing feature signal when the benefit justifies transfer cost; check the bundle output instead of assuming a browser guard removes server tracing.
- [server-auth-actions](../upstream/vercel/react-best-practices/rules/server-auth-actions.md): treat every Server Action as a public endpoint; validate inputs and perform authentication and authorization inside the action before mutation, even when middleware or page guards also exist.
- [server-cache-react](../upstream/vercel/react-best-practices/rules/server-cache-react.md): deduplicate server work within a request with `React.cache()`; use stable primitive arguments or the same object identity, and verify the framework's fetch memoization conditions before adding a redundant wrapper.
- [server-cache-lru](../upstream/vercel/react-best-practices/rules/server-cache-lru.md): use a bounded, expiring shared cache only for intentionally reusable data; include tenant/user scope where required, define invalidation, and distinguish reuse in a warm process from cross-process persistence.
- [server-dedup-props](../upstream/vercel/react-best-practices/rules/server-dedup-props.md): preserve references when passing shared data across RSC boundaries because serialization deduplicates by identity; compare client-side derivation against sending only derived data when the original is unnecessary or the transformation is expensive.
- [server-hoist-static-io](../upstream/vercel/react-best-practices/rules/server-hoist-static-io.md): hoist immutable fonts, logos, configuration, or templates shared by every request; do not hoist request-specific, sensitive, changing, or excessively large content into permanent module memory.
- [server-no-shared-module-state](../upstream/vercel/react-best-practices/rules/server-no-shared-module-state.md): keep request and user data out of mutable module globals during SSR/RSC; pass request-local values through supported boundaries and permit only immutable data or correctly keyed shared caches.
- [server-serialization](../upstream/vercel/react-best-practices/rules/server-serialization.md): pass only fields actually consumed by client components; avoid serializing whole server records, large unused structures, or sensitive properties.
- [server-parallel-fetching](../upstream/vercel/react-best-practices/rules/server-parallel-fetching.md): compose independent server regions as siblings or children so a parent's await does not serialize unrelated fetches.
- [server-parallel-nested-fetching](../upstream/vercel/react-best-practices/rules/server-parallel-nested-fetching.md): chain each item's dependent fetch inside that item's promise, then collect with `Promise.all()`, so one slow item does not delay every other item's next stage.
- [server-after-nonblocking](../upstream/vercel/react-best-practices/rules/server-after-nonblocking.md): on a supported Next.js runtime, schedule eligible post-response work with `after()`; keep required mutations and response correctness before return, await asynchronous work inside its callback, and respect runtime limits, failure/redirect behavior, and durability requirements.
- [client-swr-dedup](../upstream/vercel/react-best-practices/rules/client-swr-dedup.md): reuse the project's client cache for request deduplication, caching, revalidation, immutable data, and mutations; the full SWR examples apply when SWR is already the chosen stack.
- [client-event-listeners](../upstream/vercel/react-best-practices/rules/client-event-listeners.md): share global listeners across component instances, track subscribers, and clean up listeners and callback registrations; the full example uses SWR subscriptions rather than one listener per hook instance.
- [client-passive-event-listeners](../upstream/vercel/react-best-practices/rules/client-passive-event-listeners.md): mark touch and wheel listeners passive when they never call `preventDefault()`; retain non-passive handling when an intentional gesture or zoom control must prevent the default.
- [client-localstorage-schema](../upstream/vercel/react-best-practices/rules/client-localstorage-schema.md): version storage keys, migrate deliberately, store only needed nonsensitive fields, and handle read, parse, quota, private-mode, and disabled-storage failures.
- [rerender-defer-reads](../upstream/vercel/react-best-practices/rules/rerender-defer-reads.md): read dynamic state on demand inside callbacks when rendering does not depend on it; avoid unnecessary subscriptions while preserving reactive values that affect the visible UI.
- [rerender-memo](../upstream/vercel/react-best-practices/rules/rerender-memo.md): isolate expensive rendering so early-return paths skip it, and memoize only where it helps; account for existing React Compiler optimization.
- [rerender-memo-with-default-value](../upstream/vercel/react-best-practices/rules/rerender-memo-with-default-value.md): hoist optional array, object, and callback defaults into stable constants when fresh instances defeat an otherwise useful memoized boundary.
- [rerender-dependencies](../upstream/vercel/react-best-practices/rules/rerender-dependencies.md): depend on the primitive values an effect actually uses and compute derived conditions before the effect; retain all real reactive dependencies.
- [rerender-derived-state](../upstream/vercel/react-best-practices/rules/rerender-derived-state.md): subscribe to a derived condition such as a media-query boolean when continuous raw values do not affect the result.
- [rerender-derived-state-no-effect](../upstream/vercel/react-best-practices/rules/rerender-derived-state-no-effect.md): derive values directly from current props and state instead of mirroring them through state and effects; use deliberate keyed resets when identity changes.
- [rerender-functional-setstate](../upstream/vercel/react-best-practices/rules/rerender-functional-setstate.md): use functional updates whenever the next state depends on prior state to avoid stale closures and unnecessary callback dependencies; direct updates remain appropriate for fixed or argument-derived values.
- [rerender-lazy-state-init](../upstream/vercel/react-best-practices/rules/rerender-lazy-state-init.md): pass an initializer function for expensive initial state; keep initialization pure and SSR-safe, and avoid unnecessary function wrappers for cheap primitives or literals.
- [rerender-simple-expression-in-memo](../upstream/vercel/react-best-practices/rules/rerender-simple-expression-in-memo.md): compute cheap primitive expressions directly when memoization and dependency comparisons cost more than recomputation.
- [rerender-split-combined-hooks](../upstream/vercel/react-best-practices/rules/rerender-split-combined-hooks.md): split unrelated effects or expensive calculations with independent dependencies so one change does not rerun every task; account for React Compiler before adding manual memoization.
- [rerender-move-effect-to-event](../upstream/vercel/react-best-practices/rules/rerender-move-effect-to-event.md): execute submit, click, and drag side effects in their actual event handlers instead of triggering them through state-plus-effect chains that can repeat an action.
- [rerender-transitions](../upstream/vercel/react-best-practices/rules/rerender-transitions.md): mark genuinely nonurgent rendering updates as transitions while keeping input feedback urgent; moving state priority does not move expensive synchronous JavaScript off the main thread.
- [rerender-use-deferred-value](../upstream/vercel/react-best-practices/rules/rerender-use-deferred-value.md): defer expensive list, chart, or derived rendering driven by urgent input; ensure expensive work is keyed to the deferred value so it does not still recompute on every urgent render.
- [rerender-use-ref-transient-values](../upstream/vercel/react-best-practices/rules/rerender-use-ref-transient-values.md): keep frequently changing transient values in refs when their changes should not render UI; retain state for values that must update the visible interface.
- [rerender-no-inline-components](../upstream/vercel/react-best-practices/rules/rerender-no-inline-components.md): define component types outside parent renders and pass data through props so rerenders do not remount children, reset state, lose input focus, or restart effects.
- [rendering-animate-svg-wrapper](../upstream/vercel/react-best-practices/rules/rendering-animate-svg-wrapper.md): consider animating an HTML wrapper around an SVG for transform/opacity animation and confirm browser rendering behavior; retain SVG internal transform origins when animating its parts.
- [rendering-content-visibility](../upstream/vercel/react-best-practices/rules/rendering-content-visibility.md): use `content-visibility: auto` and an appropriate intrinsic size to defer off-screen layout and paint where it fits the content; verify scrolling, focus, search, and accessibility.
- [rendering-hoist-jsx](../upstream/vercel/react-best-practices/rules/rendering-hoist-jsx.md): hoist genuinely static JSX, especially large static SVG trees, when repeated creation matters; skip redundant manual hoisting already handled by React Compiler.
- [rendering-svg-precision](../upstream/vercel/react-best-practices/rules/rendering-svg-precision.md): reduce unnecessary SVG coordinate precision according to viewBox size and visible fidelity; use the existing asset optimizer and inspect the rendered result.
- [rendering-hydration-no-flicker](../upstream/vercel/react-best-practices/rules/rendering-hydration-no-flicker.md): initialize client-dependent presentation such as theme before visible hydration when the framework supports it; guard storage failures, respect CSP, safely serialize data, and never infer authorization from client presentation state.
- [rendering-hydration-suppress-warning](../upstream/vercel/react-best-practices/rules/rendering-hydration-suppress-warning.md): use hydration suppression narrowly for an understood unavoidable mismatch; fix unstable server/client rendering rather than hiding real bugs.
- [rendering-activity](../upstream/vercel/react-best-practices/rules/rendering-activity.md): use supported `Activity` boundaries for expensive frequently hidden UI when preserving state and DOM is useful; verify hidden-effect cleanup and restoration rather than assuming the subtree stops all work.
- [rendering-conditional-render](../upstream/vercel/react-best-practices/rules/rendering-conditional-render.md): use an explicit ternary or boolean condition when `&&` could leak `0`, `NaN`, or another renderable value into the interface.
- [rendering-usetransition-loading](../upstream/vercel/react-best-practices/rules/rendering-usetransition-loading.md): use the supported transition pending model for nonblocking updates where appropriate; preserve error reporting, response ordering, explicit cancellation, and urgent controlled-input updates.
- [rendering-resource-hints](../upstream/vercel/react-best-practices/rules/rendering-resource-hints.md): choose DNS prefetch for future origins, preconnect for imminent connections, preload for critical assets, preloadModule for likely modules, and preinit/preinitModule for resources that must also execute; avoid indiscriminate preloading.
- [rendering-script-defer-async](../upstream/vercel/react-best-practices/rules/rendering-script-defer-async.md): use `defer` for ordered scripts that need parsed DOM and `async` for independent scripts; use the existing Next.js script strategy API when applicable.
- [js-batch-dom-css](../upstream/vercel/react-best-practices/rules/js-batch-dom-css.md): batch layout reads and style writes instead of alternating them; prefer classes for shared styling and avoid forced synchronous layout during render.
- [js-index-maps](../upstream/vercel/react-best-practices/rules/js-index-maps.md): build one keyed Map when repeated linear `find()` calls dominate a hot path; preserve duplicate-key and missing-value semantics.
- [js-cache-property-access](../upstream/vercel/react-best-practices/rules/js-cache-property-access.md): cache stable repeated property lookups in measured hot loops without freezing values that can legitimately change during iteration.
- [js-cache-function-results](../upstream/vercel/react-best-practices/rules/js-cache-function-results.md): cache expensive deterministic repeated calculations when reuse justifies memory; bound and invalidate caches, preserve request isolation, and never reuse a browser authentication-result cache as server authorization.
- [js-cache-storage](../upstream/vercel/react-best-practices/rules/js-cache-storage.md): avoid repeated synchronous storage and cookie parsing with an in-memory cache; update or invalidate it on writes, other-tab changes, and externally changed cookies.
- [js-combine-iterations](../upstream/vercel/react-best-practices/rules/js-combine-iterations.md): combine repeated filter/map passes when profiling justifies it and the fused loop preserves output order and predicate semantics.
- [js-length-check-first](../upstream/vercel/react-best-practices/rules/js-length-check-first.md): compare array lengths before expensive equality, sorting, or serialization; use nonmutating comparisons and return early at the first proven difference.
- [js-early-exit](../upstream/vercel/react-best-practices/rules/js-early-exit.md): stop validation or search once its outcome is known when later iterations have no required side effects.
- [js-hoist-regexp](../upstream/vercel/react-best-practices/rules/js-hoist-regexp.md): reuse static regular expressions or memoize dynamic ones when valuable; account for mutable `lastIndex` on global/sticky patterns.
- [js-min-max-loop](../upstream/vercel/react-best-practices/rules/js-min-max-loop.md): find extrema with a single pass instead of sorting; reserve spread-based `Math.min/Math.max` for safely small arrays and handle empty data explicitly.
- [js-set-map-lookups](../upstream/vercel/react-best-practices/rules/js-set-map-lookups.md): use Set or Map for repeated membership checks when the one-time construction and memory cost are justified.
- [js-tosorted-immutable](../upstream/vercel/react-best-practices/rules/js-tosorted-immutable.md): keep props and state immutable with supported copying array operations such as `toSorted()`, `toReversed()`, `toSpliced()`, and `with()`; use copied-array fallbacks for older targets.
- [js-flatmap-filter](../upstream/vercel/react-best-practices/rules/js-flatmap-filter.md): consider `flatMap()` when one transform emits zero or more outputs and avoids an intermediate map/filter array; preserve whether valid falsy values survive.
- [js-request-idle-callback](../upstream/vercel/react-best-practices/rules/js-request-idle-callback.md): schedule noncritical background work in small idle chunks with a timeout when required and a browser fallback; never defer feedback the user is waiting for.
- [advanced-effect-event-deps](../upstream/vercel/react-best-practices/rules/advanced-effect-event-deps.md): exclude `useEffectEvent` results from effect dependencies while retaining actual reactive dependencies; invoke Effect Events only through supported effect logic.
- [advanced-event-handler-refs](../upstream/vercel/react-best-practices/rules/advanced-event-handler-refs.md): keep the latest callback in a ref when a subscription must remain stable; clean up the subscription and use supported Effect Events only for effect-local behavior, without relying on function identity.
- [advanced-init-once](../upstream/vercel/react-best-practices/rules/advanced-init-once.md): place truly app-wide initialization in the proper entry point or a deliberate once-per-app guard because components can remount; do not use a shared server module guard for request-local work.
- [advanced-use-latest](../upstream/vercel/react-best-practices/rules/advanced-use-latest.md): use supported Effect Events to read latest committed values in timers or callbacks owned by effects without stale closures; preserve genuine reactive dependencies instead of using this pattern to bypass the hooks linter.

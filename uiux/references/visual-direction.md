- Use this guide for visual direction, hierarchy, typography, color, spacing, imagery, responsive composition, and deliberate refinement; read the matching full [Anthropic reference](../upstream/anthropic/overview.md) or [Impeccable catalog](../upstream/impeccable/catalog.md) before decisions that need their detail.
- Start with the actual audience, subject, primary job, real content, constraints, and success condition; infer settled facts from the project and ask only about a material gap that changes the design.
- Read neighboring screens, components, tokens, assets, and rendered states before changing an established product; a missing design document does not erase an existing visual identity.
- Distinguish a local refinement, a new surface within an existing system, and an explicitly requested redesign; preserve identity, behavior, factual copy, and out-of-scope surfaces during refinements, and preserve product truth and constraints during redesigns.
- Choose the surface’s purpose: Persuade helps a visitor decide and act, Operate helps complete a task, Read helps understand material, and Experience lets the work itself lead; a product may contain all four modes.
- For a new or replacement visual direction, load [new-work](../upstream/impeccable/reference/new-work.md) and the relevant [Operate](../upstream/impeccable/reference/mode-operate.md), [Read](../upstream/impeccable/reference/mode-read.md), or [Persuade/Experience](../upstream/impeccable/reference/mode-persuade.md) guidance; apply its design reasoning through available tools without importing its runtime or approval ceremony.
- Derive visual character from the audience’s world and the product’s substance; explain what makes this composition specific, select one memorable feature, and give supporting elements quieter roles.
- Treat upstream anti-template warnings as a prompt to make deliberate decisions; the user’s requested aesthetic and an established system take precedence over blanket bans on a font, palette, card, border, eyebrow, or visual style.
- In task interfaces, keep navigation and controls familiar and let character live in typography, palette, density, and a meaningful signature treatment; in reading interfaces, give the frame identity while keeping the reading column calm.
- In persuasive surfaces, make the offer, credible proof, and real primary action clear in the opening; in portfolios and showcases, let the actual artifact lead rather than adding generic promotional chrome.
- Plan the hierarchy and responsive composition before polishing details; assign clear roles to title, supporting information, controls, primary action, secondary actions, and evidence, and group related content more tightly than separate sections.
- Choose typefaces for the brief and their role, keep the family count intentional, define a coherent scale and weight hierarchy, and test actual line breaks, long strings, numerals, labels, and localizations; load [typeset](../upstream/impeccable/reference/typeset.md) for the full typography workflow.
- Set readable measures and line height for content and device, preserve text resizing, and distinguish dense data from prose; numerical source heuristics are starting points, not permission to break the project’s typography or accessibility.
- Choose named color roles for surfaces, text, interactive states, and semantic feedback; verify contrast in actual contexts, preserve meaning beyond color, and load [colorize](../upstream/impeccable/reference/colorize.md) for palette strategy, perception, and systematic application.
- Make spacing, alignment, density, container width, radii, and depth consistent with their structural role; use [layout](../upstream/impeccable/reference/layout.md) to assess spatial hierarchy and geometry rather than fixing each margin independently.
- Verify real CSS precedence and computed values when spacing or typography drifts; avoid broad selector changes that quietly override neighboring components.
- Structural decoration must communicate something: numbering represents a real sequence, borders establish grouping, and labels aid understanding; remove additions whose only purpose is to make an otherwise generic layout look designed.
- Use genuine product copy, meaningful sample data labeled as illustrative when necessary, and appropriate imagery; do not fabricate testimonials, statistics, customer identities, capabilities, or proof.
- Choose an asset because it supports the composition and subject, keep its origin and usage permission, and use real contours or proper transparency when a cutout is needed; source-generated images, fonts, and logos still require their actual provenance.
- Load [visualize](../upstream/impeccable/reference/visualize.md), [region-map](../upstream/impeccable/reference/region-map.md), and [asset handoff](../upstream/impeccable/agents/impeccable-asset-producer.md) for full composition, region containment, code-versus-raster, measured fidelity, and asset quality guidance when an approved visual reference drives implementation.
- If the user asks for alternatives, vary meaningful composition or interaction choices while holding product truth and comparison conditions steady; use [prototype](../upstream/emil/skills/prototype/overview.md) and its [picker example](../upstream/emil/skills/prototype/PICKER.md) as optional implementation references, and remove experiment scaffolding when promoting the chosen design.
- For user-authorized planning, product discovery, token documentation, or component extraction, load [shape](../upstream/impeccable/reference/shape.md), [init](../upstream/impeccable/reference/init.md), [document](../upstream/impeccable/reference/document.md), or [extract](../upstream/impeccable/reference/extract.md); preserve the project’s existing documentation paths, bullet format, and source of truth.
- Record measured values and durable rules in the project’s design language document when that update is authorized; keep decisions precise enough to reproduce, distinguish global rules from component exceptions, and never copy source templates over an established project format.
- Strengthen an underexpressed design with [bolder](../upstream/impeccable/reference/bolder.md), reduce overstimulation with [quieter](../upstream/impeccable/reference/quieter.md), remove unnecessary complexity with [distill](../upstream/impeccable/reference/distill.md), and perform a final consistency pass with [polish](../upstream/impeccable/reference/polish.md); choose the operation that matches the user’s request.
- Use [clarify](../upstream/impeccable/reference/clarify.md) for labels, actions, forms, errors, permissions, empty states, and localization; write plain action names consistently through the flow, explain recovery, and let each written element do one job.
- Use [onboard](../upstream/impeccable/reference/onboard.md) for first-run value, contextual discovery, optional teaching, empty states, and help; avoid a ceremony when the user can learn by completing the task.
- Use [delight](../upstream/impeccable/reference/delight.md) for rare, earned moments and [overdrive](../upstream/impeccable/reference/overdrive.md) for explicitly ambitious effects; retain progressive enhancement, performance, accessibility, and a clear purpose.
- Use [adapt](../upstream/impeccable/reference/adapt.md) for desktop, mobile, tablet, print, email, responsive images, input methods, safe areas, and structural adaptation; do not treat every device change as uniform scaling.
- On native surfaces, load the full [iOS](../upstream/impeccable/reference/ios.md) or [Android](../upstream/impeccable/reference/android.md) rules and [native adaptation](../upstream/impeccable/reference/adapt.native.md); platform navigation, target sizes, text scaling, system controls, materials, and gestures govern the interaction.
- Load [Operate depth](../upstream/impeccable/reference/operate.md) for state-rich product UI and [craft floor](../upstream/impeccable/reference/craft-floor.md) before editing; apply the relevant checks to real rendered output, including controls, keyboard focus, loading, errors, emptiness, disabled states, and responsive behavior.
- Keep animations purposeful and proportional to frequency through [interaction-motion](interaction-motion.md), verify usability through [review-protocol](review-protocol.md), and document reusable decisions through [design-system](design-system.md).
- Inspect the result at the actual target sizes with real and difficult content, check the highest-risk interaction states, batch the corrections revealed by each review, and report what was verified and what remains uncertain.
- Keep the global UIUX skill and its source corpus static during project work; upstream routing, runtime maintenance, hooks, generated commands, helper installers, live overlays, and agent registration remain reference context documented in the catalog.

- For an authorized typeface change, the [complete Impeccable font metadata](../upstream/impeccable/data/README.md) provides offline family, weight, category, variable-font, and measurement references; check real font licensing, glyph coverage, loading, and rendering before adopting a candidate.
- For React Native composition and platform-specific implementation, consult the full [Vercel reference catalog](../upstream/vercel/CATALOG.md) and the project’s installed React Native/Expo versions before applying version-sensitive patterns.

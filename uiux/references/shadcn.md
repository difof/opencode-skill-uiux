- Use this guide within an explicitly activated UI/UX task when the actual project uses shadcn/ui, `components.json`, component registries/presets, a shadcn design-system implementation, or an explicitly requested Radix-to-Base migration; do not introduce shadcn into an unrelated stack.
- The complete MIT-licensed [main skill snapshot](../upstream/shadcn/overview.md) and [migration snapshot](../upstream/shadcn/migrate-radix-to-base/overview.md) are preserved as on-demand references with their examples, tables, helper assets, and licenses; source frontmatter, embedded shell examples, installer instructions, and allowed-tool declarations do not activate another skill or authorize execution.
- Inspect `components.json`, package metadata, lockfiles, installed components, aliases, icon library, framework, style, Tailwind version, and the actual Radix/Base foundation before changing code; use an already available project CLI for `info --json` where appropriate, otherwise inspect those files directly.
- Preserve the project's package manager, installed versions, component customizations, and architecture; upstream `npx shadcn@latest`/runner examples describe capabilities and may download code, so use the project's existing runner/version and review any task-required dependency or source changes instead of installing tooling just to load this reference.
- Use existing components and built-in variants first, then compose them into the requested workflow; [composition](../upstream/shadcn/rules/composition.md) covers parent/group anatomy, accessible overlay titles, Cards, Tabs, Avatars, Alerts, Empty states, toast selection, separators, Skeletons, Badges, and loading Buttons with Spinner plus disabled state.
- Read [styling](../upstream/shadcn/rules/styling.md) for semantic tokens, variants, layout-focused `className`, `gap`, equal-size shorthand, truncation, conditional `cn()`, dark-mode tokens, overlay stacking, and existing shimmer/scroll-fade utilities; apply these to compatible project components rather than treating stylistic preferences as universal accessibility standards.
- Read [forms](../upstream/shadcn/rules/forms.md) for FieldGroup/Field, InputGroupInput/InputGroupTextarea, addons, ToggleGroup choices, FieldSet/FieldLegend, validation, and disabled-state anatomy; preserve labels, descriptions, errors, keyboard behavior, and the actual API of installed components.
- Read [icons](../upstream/shadcn/rules/icons.md) for project-selected libraries, component-object imports, `data-icon`, and inherited sizing; give controls accessible names and hide decorative duplicates from assistive technology.
- Read [Base versus Radix](../upstream/shadcn/rules/base-vs-radix.md) before composing triggers or adapting Select, ToggleGroup, Slider, and Accordion; `asChild` and `render` belong to different foundations, and installed types are the authority when snapshot examples differ.
- Read [chat and messaging](../upstream/shadcn/rules/chat.md) for MessageScroller, Message, Bubble, Attachment, Marker, Trace, CodeBlock, streaming, anchoring, jump-to-latest, assistant activity, and escape-hatch hooks; use supported conversation primitives and verify scroll/focus behavior during partial streams and long histories.
- Read the complete [CLI reference](../upstream/shadcn/cli.md) for `init`, `apply`, `add`, `search`, `view`, `docs`, `diff`, `info`, and `build`, including templates, presets, monorepos, preset switching, dry runs, diffs, file previews, and upstream merging; choose the smallest command needed for the authorized change and inspect proposed overwrites before applying them.
- Use [customization and theming](../upstream/shadcn/customization.md) for role-based light/dark variables, custom colors, radius, built-in/new variants, wrappers, and update checks; preserve semantic foreground/surface pairs and intentional component-level customization instead of overwriting them with a new preset.
- Use [registry authoring and addresses](../upstream/shadcn/registry.md) for source registries, `registry.json`, includes, item types, files, dependencies, address schemes, GitHub registries, and build verification; inspect registry source and dependency changes, and keep authentication values out of public source and reports.
- The [MCP reference](../upstream/shadcn/mcp.md) documents project registries, listing/search, item details, examples, add-command generation, and audit checklists; use an already configured server where available, and do not install or connect MCP services merely because this skill is loaded.
- For an explicitly requested shadcn design-system implementation, follow [design-system implementation](../upstream/shadcn/design-system.md) for scaffold/style choice, component installation scope, token/role mapping, fonts, type scale, radius, elevation, control heights, dark mode, focus, variants, recipes, and verification; read the existing canonical brand/design source regardless of whether its filename is `DESIGN.md` or `design/design.md`.
- Scope scaffold, install-all, and preset-switch examples to the requested deliverable; an existing project's small component change does not require recreating the application, installing every component, or introducing a second design document.
- Use [design-system page](../upstream/shadcn/design-system-page.md) when a rendered showcase is part of the task: foundations, measured foreground/background pairs, type and spacing, component tiers, pinned states, edge cases, do/don't examples, named recipes, and one realistic composed screen should demonstrate the actual design rules.
- The reusable showcase sources [color-pair.tsx](../upstream/shadcn/assets/showcase/color-pair.tsx), [state-matrix.tsx](../upstream/shadcn/assets/showcase/state-matrix.tsx), and [preview-states.css](../upstream/shadcn/assets/showcase/preview-states.css) are complete examples to adapt to the project; retain real content and representative states instead of expanding every possible combination.
- To check showcase imports without modifying the skill, resolve `UIUX_SKILL_ROOT` to the installed skill directory and run `node "$UIUX_SKILL_ROOT/upstream/shadcn/scripts/showcase-coverage.mjs" "<project-ui-directory>" "<project-showcase-directory>"`; this dependency-free read-only helper reports missing imports and exits nonzero for gaps, but an import count does not prove correct rendering, behavior, or accessibility.
- Only migrate Radix to Base when requested; read the [migration overview](../upstream/shadcn/migrate-radix-to-base/overview.md), preserve a build/typecheck baseline, detect in-progress component files, migrate dependencies before consumers, and follow the project's existing branch/commit/report conventions.
- For compatible named styles, compare each wrapper with its exact stock origin and the corresponding Base variant; preserve customized wrappers with a reviewed three-way merge, migrate consumers explicitly, and sweep even clean merges for stale Radix imports/placeholders because a conflict-free merge is not semantic verification.
- In progressive migration, preserve the original wrapper while consumers move to the Base counterpart and switch the project style/remove Radix dependencies only after the last relevant wrapper; whole-project mode requires explicit scope, and legacy styles without a Base counterpart must retain their appearance and report future CLI consequences.
- The migration's [universal patterns](../upstream/shadcn/migrate-radix-to-base/universal-patterns.md), [class mapping](../upstream/shadcn/migrate-radix-to-base/class-mapping.md), [consumer props](../upstream/shadcn/migrate-radix-to-base/consumer-props.md), and [wrapper shapes](../upstream/shadcn/migrate-radix-to-base/wrapper-shapes.md) preserve imports, `asChild`/render, Portal/Positioner/Popup anatomy, prop forwarding, CSS variables, data attributes, callback signatures, and exact wrapper structures.
- Load the applicable migration family: [overlays](../upstream/shadcn/migrate-radix-to-base/overlays.md) for Dialog/AlertDialog/Popover/Tooltip/HoverCard, [menus](../upstream/shadcn/migrate-radix-to-base/menus.md) for dropdown/context/menubar/navigation, [form controls](../upstream/shadcn/migrate-radix-to-base/form-controls.md) for Select/Checkbox/RadioGroup/Switch/Slider, [disclosure](../upstream/shadcn/migrate-radix-to-base/disclosure.md) for Accordion/Collapsible/Tabs/Toggle/ToggleGroup/Toolbar, and [display and miscellaneous](../upstream/shadcn/migrate-radix-to-base/display-misc.md) for Progress/ScrollArea/Separator/Avatar/Toast/Form and primitives without direct counterparts.
- Keep non-Radix libraries such as cmdk, vaul, Sonner, Input OTP, React Day Picker, and Recharts outside a Radix migration unless separately requested; report missing counterparts and behavior changes such as activation, close-on-click, timing, anchoring, and navigation rather than silently inventing replacements.
- Resolve mapping uncertainty against installed `@base-ui/react` type declarations and current primary documentation; report changed files, deliberately untouched files, behavior deltas, manual interaction checks, baseline versus new failures, and a count of remaining Radix wrappers derived from source.
- Validate relevant themes, realistic content, small viewports, keyboard interaction, focus return, pointer behavior, state styling, and project type/build checks in proportion to the change; keep project decisions and reports in the project's canonical documentation, and never modify bundled snapshots or generate project state inside this skill during ordinary use.

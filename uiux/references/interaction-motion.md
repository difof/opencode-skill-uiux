- Use this guide for interaction feedback, motion decisions, animation implementation and review, gestures, mobile behavior, and perceived performance; the complete [Emil catalog](../upstream/emil/catalog.md) and [Impeccable motion playbook](../upstream/impeccable/reference/animate.md) retain the detailed rules and working examples.
- Start with the task and its frequency: repeated keyboard shortcuts and routine navigation should feel immediate, occasional state changes may need continuity, and rare onboarding or celebration moments may earn more expression.
- Require a concrete purpose for every animation: acknowledge input, reveal state, show a spatial relationship, preserve continuity, explain a feature, or support an intentional focal moment; do not animate merely because a static element exists.
- Read [animation opportunities](../upstream/emil/skills/find-animation-opportunities/overview.md) before adding motion broadly and [remove animations](../upstream/emil/skills/remove-animations/overview.md) when a product feels slow or busy; document rejected candidates and useful motion retained.
- Match feedback to the outcome: local actions update immediately, slower operations show honest progress without layout jumps, failures retain useful input and explain recovery, and reversible changes offer proportionate undo where appropriate.
- Keep success, error, loading, selected, disabled, hover, focus, and active states coherent; use motion as a supplement to visible state and accessible announcements, never as the only signal.
- Preserve immediate input acknowledgment and avoid delaying commits, focus, navigation, or keyboard operation until a decorative transition ends; disable repeated submissions only when the operation requires it and retain a clear recovery path.
- Use the detailed [design engineering reference](../upstream/emil/skills/emil-design-eng/overview.md), [animation builder](../upstream/emil/skills/animate/overview.md), and [component recipes](../upstream/emil/skills/animate/RECIPES.md) for exact easing, duration, spring, entrance, exit, transform, and component examples.
- Choose timing by distance, consequence, frequency, and platform; keep common feedback brief, use responsive deceleration for arrivals, and justify longer transitions by what the user needs to understand instead of copying a universal duration.
- Prefer a CSS transition for a retargetable state change, a bounded keyframe sequence for a predetermined effect, WAAPI for programmatic animation, and an existing motion library when dynamic orchestration or gestures need it; avoid a new dependency for a simple effect.
- Keep common motion within a shared token vocabulary and use a spring when velocity continuity and interruption matter; choose damping and bounce for the product’s character and do not add oscillation to functional UI by habit.
- Make entrance and exit directions spatially coherent, anchor popovers to their trigger, keep centered dialogs centered, and use a restrained visible starting scale rather than making a functional element appear from zero.
- Treat hover as input-specific, provide equivalent touch and keyboard feedback, and suppress sticky touch-hover effects; related tooltips can share an initial delay while subsequent hovers remain immediate.
- Preserve content in the default state and provide a meaningful fallback when scripts, animation APIs, fonts, or assets fail; motion must not be required to discover the page’s contents.
- Implement a deliberate reduced-motion path that reduces movement, parallax, zoom, and vestibular effects while preserving legible feedback; honor the user’s preference and pause nonessential loops when offscreen or hidden.
- Avoid `transition: all` and unnecessary layout-driven animation; prefer transform and opacity when they communicate the intended change, then profile any clip path, filter, blur, shadow, layout, or shader effect on the target device.
- Do not assume every transform, CSS animation, WAAPI animation, or clip path runs off the main thread; compositor eligibility depends on the browser, property, library version, and animation configuration.
- Use [animation performance](../upstream/emil/skills/animation-performance/overview.md) and the [performance cheatsheet](../upstream/emil/performance-cheatsheet.md) for frame budgets, main-thread contention, CSS variable inheritance, layout reads/writes, React state churn, Motion version caveats, and scoped `will-change`.
- Use [choreography](../upstream/emil/skills/choreograph/overview.md) and its [recipes](../upstream/emil/skills/choreograph/RECIPES.md) to coordinate simultaneous, overlapping, sequential, and shared-element motion; cap total delay, preserve direction, and avoid making every section a cascade.
- Make rapid reversals and repeated input continue from the current visual state without snapping, stale timers, lost focus, or accumulated delay; test entering and leaving while content changes or requests fail.
- For gesture work, read [gestures](../upstream/emil/skills/gestures/overview.md) and [Apple interaction principles](../upstream/emil/skills/apple-design/overview.md): track the finger directly, preserve release velocity, project momentum, damp boundaries, handle pointer capture and cancellation, protect against extra touches, and allow an interaction to be caught mid-motion.
- Keep gesture dismissal, scroll, focus trapping, Escape, safe areas, and accessible alternatives consistent; prefer a proven existing component when it already solves the interaction and inspect its current API before adopting it.
- For mobile web issues, load [mobile-native](../upstream/emil/skills/mobile-native/overview.md) for touch targeting, hover gating, tap response, keyboard/input zoom, viewport height, overscroll, safe areas, selection, and status-bar integration; verify actual devices when behavior depends on hardware.
- For React Native or Expo, load [animate-expo](../upstream/emil/skills/animate-expo/overview.md) and its [recipes](../upstream/emil/skills/animate-expo/RECIPES.md) for UI-thread worklets, Reanimated, gesture handling, haptics, keyboard synchronization, list entrances, screen transitions, and 120 Hz considerations.
- For native Swift or platform-specific implementation, use [implementation](implementation.md) alongside the [Swift reference](../upstream/emil/skills/write-swift/overview.md) and the matching native platform guidance; web animation assumptions do not automatically apply.
- For route-level View Transitions and framework-specific native patterns, read the complete [Vercel reference catalog](../upstream/vercel/CATALOG.md), route through [implementation](implementation.md), and verify installed React/Next/React Native versions, flags, and browser support before choosing an experimental or version-sensitive technique.
- For toast work, load [Sonner guidance](../upstream/emil/skills/ask-sonner/overview.md) and its [API reference](../upstream/emil/skills/ask-sonner/API.md); account for timers when hidden, interrupted exits, drag behavior, long content, theming, and accessible status feedback.
- Before choosing a library, read [library selection](../upstream/emil/skills/pick-ui-library/overview.md) as a capability map, retain suitable existing dependencies, and verify current maintenance, compatibility, and APIs rather than treating a pinned recommendation as mandatory.
- Use [animation vocabulary](../upstream/emil/skills/animation-vocabulary/overview.md) to translate an imprecise motion request into specific behavior, relationship, timing, and feel; confirm the result visually instead of claiming a descriptive word proves quality.
- For systematic improvement, load [improve animations](../upstream/emil/skills/improve-animations/overview.md), its complete [audit criteria](../upstream/emil/skills/improve-animations/AUDIT.md), and [plan template](../upstream/emil/skills/improve-animations/PLAN-TEMPLATE.md); apply the user’s requested audit or implementation scope and use existing project planning conventions.
- For a motion review, use [review animations](../upstream/emil/skills/review-animations/overview.md) and [standards](../upstream/emil/skills/review-animations/STANDARDS.md); cite actual code and observed behavior, and distinguish preferences and baseline heuristics from verified defects.
- Verify the fast-click, touch, keyboard, reduced-motion, interrupted-request, failed-response, focus-restoration, and slow-device paths that the changed interaction actually exposes; slow playback and frame inspection help diagnose timing, but do not replace normal-speed usability checks.
- Preserve the host UIUX request and project constraints when upstream references prescribe startup scripts, output tables, approval steps, runtime helpers, or automatic documentation changes; update project rules only when authorized and never rewrite the global skill.
